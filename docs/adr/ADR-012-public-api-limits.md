# ADR-012: пределы публичного API - лимит действий из UI, потолок инъекций и пакета

- **Статус:** принято
- **Дата:** 2026-10-31
- **Задача:** TASK-1004

## Контекст

Ревью безопасности публичного порта показало, что защита из ADR-004 п. 4 и
ADR-006 покрывает не все мутирующие REST-эндпоинты. Rate-limit из UI считал
только `POST /write` и `POST /ping`, а шесть других действий, которые пишут
в журнал и меняют состояние для всех участников (установка и сброс поведений,
восстановление снимка, инъекции), были открыты для флуда.

Дальше нашлись три неограниченных ресурса. Реестр инъекций рос без потолка,
и каждый запрос Modbus проходил линейный поиск по всем активным инъекциям.
Пакет `POST /behaviors/batch` принимал список любой длины. Дифф снимков
падал с 500 на нечисловом ключе адреса, тогда как восстановление в такой же
ситуации отвечало 400.

## Решения

1. **Одно окно действий из UI на IP.** `WEB_MAX_WRITE_PER_MIN_PER_IP`
   считает любые мутирующие REST-действия: записи, поведения, снимки,
   инъекции и пробы. Проверка - общий хелпер `_ui_action_ip`, превышение
   отвечает 429. Чтение (`GET /state`, `GET /behaviors`, журнал, метрики)
   лимитом не ограничено: оно не меняет общего состояния.

2. **Потолок активных инъекций - `MAX_ACTIVE_INJECTIONS = 32`.**
   Истёкшие и снятые инъекции слоты освобождают (ленивый TTL реестра уже
   выбрасывает истёкшие при обращении). Переполнение - `ValueError`, в REST
   это 400 со словами «слишком много активных инъекций». Значение зашито в
   коде, отдельной env-переменной не нужно: предел защищает от флуда, а не
   настраивается под сценарий.

3. **Пакет поведений не больше `MAX_BATCH_ITEMS = 2048`.** UI шлёт диапазон
   целиком - до 1024 адресов области, запас вдвое покрывает API-сценарии.
   Переполнение отклоняет схема (422), ничего не применяется. Крупные пакеты
   дробятся на несколько запросов.

4. **Нечисловой ключ адреса в диффе снимков - 400, как в восстановлении.**
   Раньше `int()` в сортировке падал и запрос уходил в 500. Текст ошибки
   повторяет стиль restore: «снимок N: некорректный адрес '...'».

## Последствия

- Один лимит на все действия означает, что 50 записей подряд закрывают и
  изменение поведений на минуту. Для живого UI это незаметно (диапазон - один
  запрос), для скриптов-автоматов - сигнал разнести действия во времени.
- Пробы `POST /ping` уже считались этим окном (ADR-004 п. 4), пересчёта
  настроек не требуется.
- Пределы зафиксированы константами `app/modbus/injection.py` и
  `app/api/models.py`; менять их - правка кода, не env.
