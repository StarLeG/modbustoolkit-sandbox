# ADR-009: дефолтные поведения-витрины slave 1..9

- **Статус:** принято
- **Дата:** 2026-10-30
- **Задача:** TASK-810

## Контекст

TASK-205 (ADR-003 п. 5) давал простые дефолты: HR/CL — constant 0, IR — счётчик
1 Гц, DI — биты счётчика секунд. Клиент, подключившийся к серверу, видит живой
только один регистр на слот IR и один паттерн на DI: проверить чтение разных
форматов данных можно лишь после настройки поведений через UI.

Просьба: в каждом Unit ID 1..9 зашить дефолтные поведения из реализованных на
определённом ряду регистров, а для дискретных сигналов взять несколько битов со
случайным переключением 0↔1.

## Решения

1. **Витрина числовых поведений — первые 12 слотов IR каждого слейва 1..9.**
   Слот 1 остаётся `counter` (max по формату, «IR — счётчик 1 Гц»), слоты 2..12
   показывают по одному поведению: sawtooth, triangle, meander, sine,
   random_uniform, random_walk, step, countdown, ramp_oneshot, follow
   (зеркало `hr:1`), constant 42. Слоты 13+ — снова `counter`. Все locked=True.

2. **DI 1..8 — `random_bit {p: 0.5}` (случайное переключение 0↔1 на каждом
   тике), DI 9..64 — `counter_bits` как раньше.** locked=True: DI генерируется
   автоматически (инвариант 2), внешние записи отклоняются.

3. **HR: демо-генераторы на последних 8 слотах значения каждого слейва 1..9**
   (slave 1 — адреса 1017..1024, слейвы 2..9 — 1009, 1011, …, 1023):
   counter 0..1000 step 10, sawtooth, triangle, meander, sine, random_uniform,
   random_walk, step. locked=True: запись в демо-слоты даёт 0x04 + журнал,
   что само по себе полезно для проверки обработки отказов. Остальной HR и весь
   CL остаются `constant 0` unlocked (shared last-write-wins, инвариант 1) —
   базовый сценарий «записал - прочитал» не меняется.

4. **Slave 10 по-прежнему без поведений** (IR вычисляются).

5. **Дефолты зависят от адреса.** `_default_for(slave, area, address)` выбирает
   поведение по слоту/адресу; общие экземпляры `Behavior` разделяются
   привязками, `remove()`/`reset()` сверяются с дефолтом конкретной привязки.

## Следствия

- Окно записи, задевающее демо-слоты HR (в том числе сырое окно 1023..1024 на
  границе карты), отклоняется целиком с 0x04. Документируется в UI.
- Клиент сразу видит разные формы сигналов: чтение FC 3/4 проверяется без
  предварительной настройки.
- Параметры демо-генераторов выбраны в пределах 0..1000, одинаково валидны для
  uint16/uint32/float — экземпляры поведений общие для всех слейвов 1..9.
