# Демо-сценарии для наладчиков

Три проверки своего Modbus-клиента на живом сервере Modbus Sandbox
`modbus-sendbox.electroman.by:5020`. Каждая занимает несколько минут,
UI сервера открыт на [modbus-sendbox.electroman.by](https://modbus-sendbox.electroman.by).

Общее для всех сценариев: демо-слоты HR и витрины генераторов заблокированы
для записи (вернётся exception 0x04), а свободные регистры общие - их может
перезаписать другой участник.

## 1. Проверить клиент на uint32 CDAB

Порядок слов CDAB - самый частый источник ошибок: старшее слово идёт вторым.

1. Откройте UI, раздел «Карта регистров», slave 3 (формат uint32 CDAB).
   Демо-слоты HR - адреса 1009, 1011, …, 1023: счётчик, пила, треугольник,
   меандр, синус и случайные величины.
2. Прочитайте из клиента FC 3 два регистра с адреса 1009 (device_id=3).
   Соберите uint32 так, как считает ваш клиент, и сравните с тем, что
   показывает UI в этом слоте.
3. Повторите для слота с синусом (адрес 1015) - значение плавное, ошибку
   порядка слов видно сразу.
4. Запишите FC 6 своё значение в свободный HR (например, адрес 1) и
   прочитайте обратно: ваш клиент должен увидеть записанное.

Что считать удачей: все демо-значения совпали с UI, запись и чтение
сходятся. Расхождение ровно в порядке слов - баг сборки 32-битного
значения у клиента.

## 2. Проверить реакцию на timeout

Клиент должен пережить пропавший ответ и восстановиться, а не зависнуть.

1. В UI, раздел «Инъекции», добавьте инъекцию: тип timeout, slave 1,
   область HR, TTL 30 секунд.
2. Запустите в клиенте цикл чтения FC 3 (любой адрес slave 1) с таймаутом
   1-2 с. Пока инъекция жива, ответов нет: клиент обязан сообщать об
   ошибке оператору, а не висеть.
3. Дождитесь окончания TTL (или сбросьте инъекцию кнопкой в UI) и
   убедитесь, что чтение снова проходит без перезапуска клиента.

Что считать удачей: клиент показал ошибку, держал заданный таймаут,
после восстановления связи продолжил работать сам. Зависший поток опроса
или необходимость переподключения вручную - провал.

Полезная вариация: вместо timeout поставьте exception-инъекцию с кодом
0x06 и проверьте обработку Device Busy.

## 3. Проверить float DCBA

DCBA - float с перевёрнутыми байтами; его часто не замечают, потому что
число выглядит «почти правдоподобно».

1. В UI, slave 9 (формат float DCBA), найдите демо-слот с синусом
   (адрес 1015) и посмотрите значение.
2. Прочитайте из клиента FC 3 два регистра с адреса 1015 (device_id=9).
3. В UI, раздел «Конвертер», выберите float и порядок DCBA, введите два
   прочитанных регистра - перевод совпадёт с живым значением слота.
4. То же самое должен проделать ваш клиент: если он собирает float как
   ABCD, значение будет выглядеть как мусор.

Что считать удачей: собранное клиентом float-значение совпало с UI
(с точностью до погрешности самого генератора).

## Если что-то пошло не так

Значения регистров меняются по таймеру и общие для всех участников -
расхождение в третьем знаке синуса или перезаписанный регистр это не
баг сервера. Снимок из UI (раздел «Снимки») замораживает картинку для
сравнения. Сервер со своими правилами можно поднять локально -
см. [DEPLOY.md](DEPLOY.md).
