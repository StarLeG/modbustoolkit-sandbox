# CLAUDE.md — контекст проекта для Claude Code

## О проекте

**modbustoolkit.electroman.by** — публичный набор инструментов для инженеров АСУ ТП
и наладчиков. В рамках этой итерации добавляем раздел
**«Публичный тестовый Modbus-TCP сервер»** — бесплатную многопользовательскую среду
для проверки Modbus-TCP клиентов.

### Что делает сервер
- Слушает TCP, эмулирует **10 unit ID** (slave 1..10).
- Поддерживает Modbus-функции: **1, 2, 3, 4, 5, 6, 16** (0x0F и прочее — запрещены).
- Значения регистров/coils живут в памяти и генерируются **движком поведений**
  (counter, sawtooth, triangle, meander, sine, random, constant и т.д.).
- Клиенты (наладчики) одновременно подключаются и работают — сервер многопользовательский.
- Web UI показывает live-состояние, позволяет настраивать поведения, инжектить ошибки,
  снимать/восстанавливать снимки.

### Источник истины по форматам
`docs/HRIR_SPEC.md` — спецификация форматов HR/IR по слейвам (uint16 / uint32 ABCD/CDAB/BADC/DCBA /
float ABCD/CDAB/BADC/DCBA, slave 10 — часовые пояса + Unix timestamp).

## Стек и архитектура (ожидаемые)

> **Первое, что нужно сделать при старте:** прочитать проект и подтвердить стек.
> Ниже — целевой стек; если в проекте уже есть FastAPI/Redis/Docker — использовать их.
> Если стек иной — согласовать до начала работ и обновить этот раздел.

- **Python 3.11+**, `asyncio`.
- **pymodbus** (async) — Modbus-TCP сервер, `ModbusServerContext(single=False)`.
- **FastAPI + uvicorn** — REST + WebSocket.
- **Docker / docker-compose** — деплой.
- **nginx** — reverse-proxy для HTTP/WS (Modbus-порт — отдельный TCP).
- Тесты: **pytest + pytest-asyncio**.
- Линтеры: **ruff**, типы: **mypy** (strict там, где принято в проекте).

### Схема процессов
```

┌──────────────────────────────────────────────────────────┐
│  uvicorn (FastAPI)                                       │
│   ├─ REST /api/modbus/*                                  │
│   ├─ WS   /ws/state                                      │
│   └─ сервисы: Engine (tick 100ms), WebStateBus, Journal  │
├──────────────────────────────────────────────────────────┤
│  pymodbus async server (TCP :5020)                       │
│   └─ 10 unit ID, доступ к тому же Engine (in-proc)       │
└──────────────────────────────────────────────────────────┘

```

Modbus-сервер и FastAPI живут в **одном event loop**, состояние — in-memory.

## Ключевые инварианты (не нарушать)

1. **HR/CL — shared last-write-wins.** Значения общие, могут быть перезаписаны другим пользователем.
   Это документируется в UI явно, не «исправляется». Исключение — демо-слоты HR
   (верхние 8 слотов, ADR-009): они locked, запись отклоняется с 0x04.
2. **IR/DI — генерируются автоматически** (по умолчанию: IR — счётчик 1 Гц и витрина
   генераторов на слотах 2..12, DI — случайные биты на 1..8 и авто-паттерн дальше;
   ADR-009).
3. **Slave 10 — только IR.** CL/DI/HR на нём отсутствуют → exception 0x02.
4. **Функция 16 — только для HR, максимум 2 регистра за запись.**
5. **Функции, кроме 1,2,3,4,5,6,16 — Illegal Function (0x01).**
6. **Event loop не блокируется.** Никаких `time.sleep`, синхронного I/O в горячем пути.
7. **Ошибка в поведении не роняет сервер.** try/except + лог + поведение переходит в `constant 0`.
8. **Секреты — только через env**, никогда в коде.
9. **Persistent storage для значений регистров отсутствует.** Перезапуск = сброс. Конфиг поведений
   можно сохранять (если в проекте уже есть Redis/БД), но это опция.

## Карта регистров (сводка)

Полная версия — в `docs/HRIR_SPEC.md`. Кратко:

| Slave | HR/IR формат | Адреса HR | Адреса IR | CL | DI |
|---|---|---|---|---|---|
| 1 | uint16 AB | 1..1024 | 1..1024 | 1..64 | 1..64 |
| 2 | uint32 ABCD | 1,3,…,1023 | 1,3,…,1023 | 1..64 | 1..64 |
| 3 | uint32 CDAB | 1,3,…,1023 | 1,3,…,1023 | 1..64 | 1..64 |
| 4 | uint32 BADC | 1,3,…,1023 | 1,3,…,1023 | 1..64 | 1..64 |
| 5 | uint32 DCBA | 1,3,…,1023 | 1,3,…,1023 | 1..64 | 1..64 |
| 6 | float ABCD | 1,3,…,1023 | 1,3,…,1023 | 1..64 | 1..64 |
| 7 | float CDAB | 1,3,…,1023 | 1,3,…,1023 | 1..64 | 1..64 |
| 8 | float BADC | 1,3,…,1023 | 1,3,…,1023 | 1..64 | 1..64 |
| 9 | float DCBA | 1,3,…,1023 | 1,3,…,1023 | 1..64 | 1..64 |
| 10 | uint16 AB (IR only) | — | 1..268, 300..301 | — | — |

Slave 10: `1 + 10*Z` … `8 + 10*Z`, Z=0..26 (0..14 → UTC+00..UTC+14; 15..26 → UTC−01..UTC−12).
IR 300..301 — Unix timestamp, uint32 ABCD, точность ±0.5 с. «Дырки» в блоках → 0.

Демо-поведения по умолчанию (ADR-009): IR слоты 2..12 каждого slave 1..9 — витрина
генераторов, DI 1..8 — случайные биты 0↔1, последние 8 слотов HR (slave 1: 1017..1024,
слейвы 2..9: 1009, 1011, …, 1023) — демо-генераторы. Всё это locked=True: внешняя
запись отклоняется (0x04 + журнал). Остальной HR/CL — constant 0, запись разрешена.

## Движок поведений (сводка API)

```python
class Behavior:
    kind: Literal["constant","counter","sawtooth","triangle","meander","sine",
                  "random_uniform","random_walk","ramp_oneshot","countdown",
                  "step","follow","toggle","pwm","random_bit","counter_bits","follow_bit"]
    params: dict
    locked: bool = False
```

- Тик 100 мс; привязка `(slave, area, address) → Behavior`.
- `locked=True` → Modbus-запись игнорируется (возвращать 0x04 Server Failure + запись в журнал).
- REST:
  - `GET    /api/modbus/behaviors`
  - `PUT    /api/modbus/behaviors/{slave}/{area}/{address}`
  - `POST   /api/modbus/behaviors/batch`
  - `POST   /api/modbus/behaviors/reset` (`all` или `{slave}`)

## Соглашения по коду

- Все публичные модули — с type hints; mypy там, где в проекте включён.
- Логирование — `structlog` или `logging` в формате проекта; никаких `print`.
- Тесты рядом с кодом: `tests/` (unit) и `tests/integration/` (pymodbus-клиент).
- Никаких «магических» портов/адресов — только через константы и env.
- REST-роуты — префикс `/api/modbus/`; WS — `/ws/state`.
- Имена слейвов/областей — строго `slave:int`, `area: Literal["cl","di","hr","ir"]`.

## Правила для Claude Code в этом проекте

1. **Сначала прочитать проект** (`ls`, `cat pyproject.toml`, посмотреть `app/`, `Dockerfile`,
   `docker-compose.yml`, `nginx/`, `.github/workflows/`) и **подтвердить стек** перед кодом.
2. Если стек отличается от заявленного — **остановиться и спросить** пользователя.
3. Работать по задачам из `ISSUES.md`, в порядке приоритета.
4. Каждая задача — отдельный коммит, сообщение в формате `feat(modbus): …` / `test(...)`.
5. Не добавлять Modbus-функции вне списка 1,2,3,4,5,6,16.
6. Не хранить значения регистров на диск.
7. Не блокировать event loop.
8. Все новые env-переменные — в `.env.example` и в `CLAUDE.md` (секция «Env»).
9. Перед PR — `pytest`, `ruff check`, `mypy` должны быть зелёными.
10. Если задача из `ISSUES.md` требует решения, влияющего на архитектуру — сначала
    добавить запись в `docs/adr/` (Architecture Decision Record).
