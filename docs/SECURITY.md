# Ревью безопасности публичного порта

Разбор от октября 2026 (TASK-1004) перед публичным запуском
modbustoolkit.electroman.by. Сервер сознательно открыт всем: без регистрации,
с общими регистрами и публичным Swagger. Задача ревью - убедиться, что
открытость не превращается в падение, утечку чужих данных и раздувание
памяти.

## Что проверено и какие выводы

Секретов в коде нет. Конфиг читается только из env (`.env.example` -
образец), ключей и токенов в репозитории не нашлось. Публичный Swagger
(`/api/docs`, `/api/openapi.json`) оставлен намеренно: документация API -
часть продукта, скрывать нечего.

`/healthz` отвечает одним словом. `{"status":"ok"}` без версий, путей и
имён хостов. Ничего лишнего healthcheck не отдаёт.

Утечек состояния нет. Снимки и значения регистров - общие по определению
(инвариант 1), чужих персональных данных сервер не хранит. IP в журнале
событий - задокументированная особенность (TASK-505): она помогает наладчикам
разбирать конфликты перезаписи, и убирать её мы не стали.

SSRF через пробу соединения закрыт. `POST /ping` опрашивает собственный
Modbus-порт по loopback; адрес цели берётся из конфига, а не из запроса.
Дикий хост в запросе пробы невозможен.

UI без XSS. Статический интерфейс строит DOM через `createElement` и
`textContent`; `innerHTML` используется только для очистки узлов. Значения
регистров и журнал вставляются текстом.

## Найденные проблемы и что сделано

Четыре находки закрыты правками от 2026-10-31, каждая с тестом.

1. **Лимит из UI считал только записи.** Шесть мутирующих эндпоинтов
   (поведения, сброс, восстановление, инъекции) не участвовали в rate-limit,
   и флуд через них раздувал журнал и менял состояние для всех участников.
   Теперь все действия из UI считаются одним окном на IP, ADR-012.

2. **Реестр инъекций рос без потолка.** Каждый Modbus-запрос искал
   подходящую инъекцию линейно, так что копившиеся записи замедляли и
   сервер, и клиентов. Потолок активных инъекций - 32, снятие и TTL слоты
   освобождают.

3. **Пакет поведений без ограничения длины.** Один запрос мог нести тысячи
   элементов, и каждый писался в журнал. Потолок - 2048 элементов, диапазон
   UI (до 1024 адресов) проходит как есть.

4. **Дифф снимков падал с 500 на нечисловом адресе.** Клиент, приславший
   мусорные ключи адресов, получал пятисотку вместо внятной ошибки. Теперь
   это 400 со словами про некорректный адрес, как у восстановления.

## Действующие лимиты

| Что ограничено | Предел | Где задан |
|---|---|---|
| Modbus-соединений с IP | 20 | `MODBUS_MAX_CONN_PER_IP` |
| Modbus-записей на соединение | 200/с | `MODBUS_MAX_WRITE_PER_SEC` |
| Действий из UI на IP (записи, поведения, снимки, инъекции) | 50/мин | `WEB_MAX_WRITE_PER_MIN_PER_IP` |
| Активных инъекций одновременно | 32 | константа `MAX_ACTIVE_INJECTIONS` |
| Элементов пакета поведений | 2048 | константа `MAX_BATCH_ITEMS` |
| Время жизни инъекции | 300 с | `INJECTION_MAX_TTL_S` |
| Задержка инъекции delay | 5000 мс | константа `MAX_DELAY_MS` |
| Записей журнала в памяти | 1000 | `JOURNAL_SIZE` |
| Размер тела запроса | 1 МБ | nginx `client_max_body_size` |

Значения регистров живут только в памяти: перезапуск всё сбрасывает,
долговременной истории для утечки нет.

## Остаточные риски

IP за обратным прокси. nginx stream пробрасывает Modbus-соединение как
есть, и лимиты Modbus-стороны видят адрес nginx, а не клиента. Для
Modbus-порта это ограничение протокола: реальный IP без поддержки PROXY
protocol недоступен. Web-сторона видит настоящие адреса через
`X-Forwarded-For` (uvicorn доверяет только `FORWARDED_ALLOW_IPS`).

Общее окно действий. Скрипт, тратящий 50 записей в минуту, закрывает и
изменение поведений на эту же минуту. Это плата за один понятный предел на IP;
для легитимного UI (диапазон - одним запросом) запаса хватает.

Публичный журнал с IP. Любой участник видит адреса других. Для
многопользовательского стенда это осознанный выбор (TASK-505), но если
политика хостинга потребует анонимности, поле `ip` нужно вырезать из ответа
`GET /journal`.

## Рекомендации по хостингу

В nginx для HTTP-зоны стоит добавить `limit_req` (например, 10 запросов в
секунду на IP с небольшим запасом): это отсечёт примитивный флуд до FastAPI
и разгрузит event loop. Модbus-порт отдельной TCP-зоной в stream уже
защищён лимитами соединений приложения. Плюс обычные меры: держать контейнер
под непривилегированным пользователем, обновлять базовый образ, логи из
`LOG_FORMAT=json` собирать шиппером платформы (ADR-011).
